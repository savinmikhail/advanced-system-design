#### 2.2.0. Две базовые стратегии шардирования (в двух словах)

1) **Hash-based** (по хешу ключа).
    - Берём `shard = hash(key) % N`.
    - Проблема: при смене `N` “переезжает” почти всё.
    - Поэтому на практике часто используют **consistent hashing** и/или **виртуальные шарды** (logical shards / vnodes): это уменьшает объём переезда и даёт более тонкий баланс.

2) **Directory-based** (через “таблицу маршрутизации”).
    - Есть отдельная мапа: `key-range/tenant/user -> shard`.
    - Плюс: можно перекидывать часть ключей между шардами без тотального пересчёта.
    - Минус: появляется ещё один критичный компонент (directory), который надо хранить надёжно и быстро.

Этого понимания обычно достаточно, чтобы уверенно отвечать на вопросы на собеседовании.
